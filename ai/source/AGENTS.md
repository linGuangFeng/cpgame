# CPGame 工作区统一规则

所有模型必须先读本文件、根目录 `复刻要求.md` / `抓包要求.md`、相关 `skills/*/SKILL.md`，再读当前游戏 protocol/ 下协议三件套与游戏规则。用户当前要求优先，业务正文高于 skill、旧代码和历史文档；游戏规则仅补充游戏事实，不能放宽通用硬约束。

## 与 FC 同步的通用口径

本次复制同一套通用业务约束：独立 Java 核心；Demo HTTP 请求/响应；官方体验参考保持原站；正式规则生成完整局存 Redis；包括0倍在内全部试玩结果读 Redis，空池报错；禁止现场造局、样本模板拼接、样本中奖组合及目标奖金反推。默认总尝试1亿/每批1000，按批中性→逐牌单独放大→复位，必需配置显式中文说明；默认放大3倍，失败计数不补足；普通/Mary容量300/50，各家族类型0默认、1/2/3…扩展；实际倍数单位逐游戏核实，生成器倍率上下限直接填写最终入 Redis 的整数缓存倍率，过滤和 key 使用同一个整数，禁止二次换算。详见正文各节。

第十五节防假生成审计必做：逐场景可达范围、入库前事实/结构多样性及倍率分布、拒绝原因；区分生成量、唯一局数、倍率数和保留存量。样本数量少不能定义规则上限，桶多或能玩不能证明生成完整。历史游戏不因同步规则自动通过。

## CP 专属工程约定（不复制 FC 游戏事实）

- 工作区即 cpgame，后台为 `admin/`；使用当前 CP 后台入口，不照搬 /FC 或 FC 的 ../admin。游戏路径沿用本仓现有 ID-Name。
- Redis 连接以 `generator/1809-mac-Freedom-Day/dist/generator.properties` 的连接配置为准；不读取/展示凭据到报告，不照搬 FC DB15。各游戏 redis.game-id 保持原值。
- 本次只改规则文件，不自动改现有 properties 数值、缓存版本或已部署逻辑。后续迁移按正文显式实施并验证；新规则默认值不是批量覆盖旧配置的授权。兼容差异逐游戏记录，不能将旧实现视为规则例外。
- 配置按连接→game-id/版本→次数/批次→容量→游戏限制→倍数范围→权重分段，注释中文。58、2470等旧属性名须先核实实际读取代码，不凭空加别名。
- 构建需交付 generator/<游戏>/dist 的 Loader 和 server-api/<游戏>/dist/controller.jar；核对实际 dist 产物时间和哈希，不能只检查 target。
- 原站资源/captures/fixtures/publish 只补缺，不清空重来。Demo 修复要进原页面真实操作，不能只看首页200；全零结果也须来自正式生成的 Redis 完整局。
- 原始取证入口、账号选择和 CP CDN/S3 发布流程保留在 cpgame-capture / cpgame-s3-upload skill；复刻实现使用 cpgame-remake。官方参考每次重新获取当前有效体验链接；不照搬 FC GetDemoUrll1、SmartFox、夜市赔表、NM2或×100。
- 抓包统计可支持已验证的权重/联合分布，但不能以有限样本表替代规则生成。统计模型不打入无状态核心；仅把规则所需事实传入核心。

## 跨模型同步

唯一编辑点 `ai/source/`，运行 `python3 ai/sync-ai-rules.py` 后运行 `--check`。根目录正文、AGENTS、CLAUDE、skills 和各厂商目录均由其生成。Codex、Claude、Cursor、Grok、Copilot读取一致的约束；自动加载能力有差异，所有入口均要求主动读取根规则。旧版备份仅供追溯。

## 本次同步的适用范围

这里只同步规则、约束及 skill，不执行补抓、上传、生成、部署或旧游戏批量迁移。旧文档所述现场0倍生成、允许模板表灌数、以样本最大值当规则上限均已由新版正文替代；发现旧代码仍如此时记录差距并按后续任务修复，不能称已符合新规则。


### 变更后的交付包（完成硬门槛）
按《复刻要求》第十六节：相关代码、依赖、资源或随包配置变更后，必须重新构建并更新所有受影响的实际交付包及下载归档；核对页面下载/下次“运行”引用路径、构建与 dist/发布副本内容一致，不能只更新 target。共享核心改动同时检查依赖包。已启动的进程不用管，不为完成打包自动重启或中断任务；保证用户下载和下次新启动取得最新包即可。交付说明实际包路径及验证结果，失败不能宣称已更新。仅规则/文档改动不影响包时不要求重打包。

### 免费中再次触发默认关闭
按《复刻要求》第十七节：默认免费过程中不再次触发/追加免费，只有用户针对该游戏特别说明才开启。记录为用户本地策略 DISABLED_BY_DEFAULT_POLICY，与官方规则事实分开；不列为默认范围的待补功能，不自动开启，也不自动提升其他未验证项。正常进入免费、原有计奖/倍率不受影响。现有拒绝相关候选的方式可沿用，计尝试且不补足；原始审计保留，当前解释为策略过滤。单游戏例外写入协议和游戏规则。
