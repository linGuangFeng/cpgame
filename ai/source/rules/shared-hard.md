# HARD — CPGame 复刻总则

本文件是两份根目录业务正文和 `AGENTS.md` 的摘要；适用顺序见工作区 `AGENTS.md`。单游戏规则、skill 与历史实现不能放宽这些要求。

## 1. 交付什么
- 迁到线上的是**游戏核心**，不是整份 Demo。
- **CPGame 核心必须用 Java 实现**（规则、编解码、组结果/Si 对等结构）；对外仍是可被委托层调用的入口（类 SiUtil 职责，Java API / 独立 JAR）。
- Demo 壳（Lab、FakeSFS、本地 host、选局）可用其他语言，**直接调用同一 Java 核心**；核心不得依赖壳。

## 2. Demo vs 线上
- Demo：允许**每个游戏整包独立**，方便试玩对照。
- 线上：一类复刻类型**共用一套委托**（History / Controller 等，首次可参考 Demo 写）；**每个游戏只独立 Java 核心**。
- 核心文件必须**相对独立**：可单独编译、单测、抽出迁入 `bf`（由 Java/其他委托直接调用 Java 核心）。

## 3. 核心入口边界（Java）
- 输入一律由调用方传入：已选好的结果、押注（bet/cs/ml 等）、余额、单号、步进索引、税点等。
- 输出：页面协议需要的结果结构（Si 对等）。
- 禁止：抽奖、读 Redis 选局、扣款/写库、读用户或租户配置、绑 Lab/端口。
- 禁止在 Controller、Demo 前端或生成器壳内另写玩法顶替独立 Java 核心（取证脚本不承担玩法）。

## 4. 缓存结果编码
- 尽量短。优先**单字符**符号；特殊含义用**单字符+数字**。
- 禁止逐格逗号牌面（反例：`H1,A,3,1,3`）。
- 任一分隔符出现次数 ÷ 串长 **> 20%** → 编码不合法，须重做。
- 编解码实现在 **Java 核心**内，与 Demo 壳语言无关。

## 5. 验收
- 不启 Lab：用 Java 单测（或最小调用方）构造入参 → 调核心 → 得到合法结果结构。
- Demo 能玩不能替代核心验收。
- 完整复刻还须通过 `AGENTS.md` 的证据与 Lab 点击验收，交付验证结果、截图和能力缺口。

## 6. Demo 结果源与原站证据
- Demo 壳从 `AGENTS.md` 约定的 Redis 读取预生成完整局，再把结果注入 Java 核心。无数据时不得用 fixtures、内存结果池或现场随机补位。
- 原站资源与规则证据按《抓包要求》采集；本地 Lab、FakeSFS、Redis 结果不能冒充原站样本。


## 7. 牌阵与样本权重
- 必须解析每个玩法阶段的符号位置禁出、每列数量上限、互斥 / 堆叠与补牌规则，附证据并进入协议、单游戏规则和 Java 校验；未知不臆断。
- 默认权重来自原站可解析样本的分组出现频率，保留统计与偏差；禁止本地样本或猜测冒充官方统计（《抓包要求》3.3、3.4）。
- 离线生成按生成批次循环「不放大 → 按固定顺序逐牌放大 → 不放大」；每牌倍数可配，默认 3；每轮恢复基础值，只放大一牌，无效候选计入尝试次数且不补足。阵型限制优先于权重，同批所有完整局及 Step 使用本批策略；遵守《复刻要求》第九节的完整约定，不能把此策略称为官方概率。


## 管理列表游戏封面（硬约束）

每个交付游戏必须有管理 / Lab 列表实际引用且能正常显示的有效封面，与游戏 ID / 名称对应。优先采用已观测到的官方游戏封面；缺少时可用真实游戏截图并注明来源。禁止错游戏、空白 / 通用占位图、失效或带过期 token 的链接及伪装图片。保存稳定本地资源，核对管理端实际读取路径与图片解码，并真实打开列表检查加载、主体与裁切，留截图；未通过须标记缺口。完整要求见《复刻要求》第十节。


## 采集完成判定（硬约束）

先实际阅读本游戏帮助、赔表、配置及前端规则并记录来源，再建立逐玩法采集计划 / 覆盖表。遵守《抓包要求》第四节：至少 10 个去重可解析完整原站 Round，基础中奖 / 未中奖各至少 3 个、实际存在的特殊模式各至少 2 个完整 Round，且关键玩法证据闭环，才可声明对应采集范围完成；这些数量只是防草率门槛，不是充分性证明。200 / 100 / 30 改为扩展参考量，按缺口分批补采，3000 为总尝试上限。提前停止必须给出样本索引、覆盖结论和停止报告；没触发不等于不存在。默认权重统计单独验收。样本不足允许继续已确认部分实现，禁止因此宣称采集或完整复刻完成；1～9 局只能是初步取证。不得自动提升历史游戏验收状态。


### 生成次数与结果容量统一口径

按《复刻要求》第九节：总生成尝试次数仅 `generation.count`（默认 1 亿），每批 `generation.batch-size`（默认 1000）；一轮权重等于一批，末批按剩余次数，失败候选不补足。Java 分类有效完整局，逐批按模式 × 倍数写 Redis。各桶容量可配并可逐桶覆盖，追加后保留最新 N 个、淘汰最旧结果；此授权仅限当前结果桶，不能清库。尝试数、有效数和现存数分别报告。验证显式小批量，不能自动跑默认 1 亿次。


### Redis 家族 / 类型映射

按《复刻要求》第十一节：普通 PerKeyList/BetLog 与 Mary（免费选择 / 免费特色）MaryKeyList/MaryLog 两个家族，各有默认类型 0、扩展类型 1、2、3、4…；不是固定四种 key。无关免费特色的额外场景走普通扩展类型，不把“特殊”一律归 Mary。先核实游戏入口与完整局，再记录稳定映射及 key / 倍数单位。普通容量默认 300、Mary 默认 50，支持按类型及倍数桶覆盖。管理端须发现任意实际类型编号及相同编码命名空间，不能仅枚举 0..3。参考 CP2470 普通/转盘/特色分别 Per0/Per1/Mary0，CP2300 三种购买分别 Mary0/1/2，禁止照搬其玩法。


### 显式配置与中文注释

遵守《复刻要求》第十二节：不要求 Redis namespace 或版本号，不设 v0 等默认版本，不因缺少 redis.namespace 判为配置缺项；不得为满足规则强加版本前缀。沿用当前游戏实际 key 合同，生成器、Controller 与管理端保持一致。其余必需配置仍须显式填写，包括每牌 weights.boost.<符号>=3；注释、单位、示例和可选逐桶容量继承规则用中文。已有前缀是项目现状，不是通用必需项；修改现有 key 须单独验证，不能因此清库。

- Redis 连接超时默认 30 秒，显式配置 `redis.connect-timeout-ms=30000`，代码默认值同步；详见《复刻要求》第十二节。


### 试玩与正式生成链路（硬约束）

遵守《复刻要求》第十三节：试玩配置必须指向 Controller 实际配置，与生成配置分开；Demo 只从 Redis 读正式生成器产生的完整局，使用同一 Java 核心，不得另写玩法、现场造局或由 AI 手工准备中奖结果供验收。生成按游戏规则和符号分布先生成事实再计奖，禁止按目标奖金反推牌面或用采集完整局当模板。交付正常生成运行记录及试玩实际取局 key / 哈希。试玩支持各场景及六档实际押注倍数概率（0、(0,5]、(5,20]、(20,50]、(50,100]、(100,10000]），抽目标后只向下找同场景最近有效桶，可跨档但不得换场景或造局。无数据明确报错。索引整数放大系数按游戏核实或用户指定；生成器倍率上下限配置直接填写最终写入 Redis 的整数缓存倍率，范围过滤、ZSET score 与列表 key 使用同一个整数，禁止配置后再次乘除；核心接口单位不得重复换算。


### Java 与 Demo HTTP 迁移约束
遵守《复刻要求》第十四节：C++ 已弃用，所有既有核心边界与游戏规则原样适用于 Java；只维护一套独立 Java 核心，Demo 与生成器共享。Demo 使用 HTTP，官方体验参考1保持原站方式。逐游戏记录与原站源文件的差异、文件范围及未验证项，语言迁移不能改变玩法或削弱 Redis / 采样 / 验收约束。


### 防样本模板假生成（验收硬约束）
遵守根目录《复刻要求》第十五节，覆盖每个普通/免费/转盘等场景：审查正式生成调用链，禁止抽采集局、拼接样本或固定样本中奖组合冒充规则生成；区分有证据的有限规则表与有限样本模板。逐场景建立规则允许/实现支持/配置启用/实际观测的可达范围表；用正式入口做显式小规模审计，按完整事实及结构统计入库前多样性、倍率分布和拒绝原因，分清生成次数、唯一局数、ZSET 倍率数及保留后 LLEN。只有随机调用、很多结果、迁移一致或页面可玩不能判合格；桶少也不能直接判假生成，更不能为凑桶造倍率。样本模板或无依据缩窄分支判 FAIL，证据不足标 PARTIAL / SAMPLE_INSUFFICIENT。报告写入 reports/{ID}/generation-audit.json 或等价文件，并链接协议/游戏规则；历史游戏不因新增规则自动通过。


### 变更后的交付包（完成硬门槛）
按《复刻要求》第十六节：相关代码、依赖、资源或随包配置变更后，必须重新构建并更新所有受影响的实际交付包及下载归档；核对页面下载/下次“运行”引用路径、构建与 dist/发布副本内容一致，不能只更新 target。共享核心改动同时检查依赖包。已启动的进程不用管，不为完成打包自动重启或中断任务；保证用户下载和下次新启动取得最新包即可。交付说明实际包路径及验证结果，失败不能宣称已更新。仅规则/文档改动不影响包时不要求重打包。

### 免费中再次触发默认关闭
按《复刻要求》第十七节：默认免费过程中不再次触发/追加免费，只有用户针对该游戏特别说明才开启。记录为用户本地策略 DISABLED_BY_DEFAULT_POLICY，与官方规则事实分开；不列为默认范围的待补功能，不自动开启，也不自动提升其他未验证项。正常进入免费、原有计奖/倍率不受影响。现有拒绝相关候选的方式可沿用，计尝试且不补足；原始审计保留，当前解释为策略过滤。单游戏例外写入协议和游戏规则。
