# runRedis 生成失败修复与验证（2026-09-15）

交付了 8、16、32、33、52、61、1090、1809、1830、1910 的新 generator/dist JAR。每个新包已核对 target/dist 的 SHA-256；详见 delivered-jars.json。未改动线上 Redis 连接、生成目标、用户缓存和已有任务状态。

## 修复

- **1830**：连消补牌前先放好所有列的保留符号，Scatter 限制计入后续列；免费连消也使用免费盘面上限。符号数量和局长超限使用专用候选拒绝异常，由生成循环丢弃重抽。配置错误、编码不一致和 Redis 异常仍报具体失败。0..0 范围允许生成纯零倍结果，生成目标不被每桶保留数量限制。
- **1809**：禁用 Ball 的普通无奖生成过程中，第三轴安全替换符号也遵守 Ball 权重为 0 的约束；避免长时间运行偶发重新插入 Ball 后终止。零倍上界配置允许为 0。
- **8 / 16 / 32**：支持后台传入的 `--config 路径`，同时保留单个路径和 `--config=路径`；继续拒绝缺参和多余参数。
- **52**：有默认值的最小倍率和特殊桶保留数量不再错误地要求旧交付配置必须显式填写。
- **33 / 61 / 1090**：倍率范围按实际倍数比较；Redis 中以百分之一倍存储的整数先除以 100 再筛选。未改变缓存键和载荷格式。
- **1910**：免费重触发超过安全局长时丢弃该候选；整体倍率超过 max-win-units 时在入队前丢弃，不再交给最终验证抛错。配置和独立校验异常仍可见。
- **后台**：失败状态可点击，弹窗独立读取原因与日志，不依赖缓存连接。生成进程使用真实退出码判定结果，避免缺少固定完成标记的成功进程被误报失败；历史失败日志也能提取具体原因。

## 验证范围

- 39 个交付目录逐一使用交付配置副本做小量运行：37 个 Redis 生成器全部实际写入隔离 Redis，2 个实时结果目录工具（2、1400）正常退出且无需 Redis。仅降低生成数量并替换隔离连接，不放宽倍率筛选范围。明细见 isolated-final.json。
- 子进程禁止连接非本机 Redis、监听端口和执行外部进程；除 2470 的单个临时报表文件外禁止写本地文件。隔离 Redis 随测试销毁。
- 1830 以普通 400、特殊 100、批次 31、连续中奖上限 2、免费上限 12 测试：17 批、500 条、丢弃超限候选 368 次，最终 COMPLETED，退出码 0。最后一批 4 条，未丢失尾批。
- 1830 的 10000 候选回归含拒绝与继续生成；保留 Scatter 位置的定向回归修复前可复现 6 个超过 4 个上限。
- 1809 新增 10000 次禁 Ball 回归，并通过现有 100000 次无奖/概率检查。
- 后台 26 个测试、1830 28 个测试、1809 29 个测试、52 13 个测试、33 2 个测试、61 9 个测试、1090 3 个测试通过；16/32 CLI 和已有自检、1910 候选上限自检通过。
- 浏览器实际验证：点击失败显示具体配置错误和日志、关闭、键盘 Enter 打开；页面无 JavaScript 异常。截图见 failure-dialog.png。

这些是定向回归及小量生成检查，不代表所有游戏均已完成长时间或穷尽概率状态验证。

## 后台生效步骤

新后台包已放入 `admin/target/cpgame-admin-0.1.0-SNAPSHOT.jar` 和 `admin/var/cpgame-admin.jar.next`。当前 Windows 运行进程尚未重启，因此线上失败弹窗尚未生效。请在 Windows 项目根目录执行：

```bat
admin\restart.cmd --deploy
```

该脚本只替换并重启后台主进程。生成器 dist 新包下次点击 runRedis 即会使用。
