# Monster Slayer 2300 protocol specification

Rules version `2300-monster-slayer-v4-base-bet-multiplier`; rules hash `86af201a56e901c629e2f8d202b515b5d31fad77956ac8353b6b8886e385b61c`.

The original Cocos page calls `POST /cp/config/initialData`, `POST /cp/account/getUserInfo`, `POST /cp/single_game.Game/initRoom`, `POST /cp/single_game.Game/gameResult`, and the two captured History endpoints. Requests are form encoded. A paid start is `type=1`; purchase starts are `type=3/4/5` (`SPECIAL_BUY_ONE/TWO/THREE`, buy multiples 60/500/200); every evidenced continuation is `type=2`. The response envelope is `{code,data,msg,time}`. `f.gt` 4 (`FREESPIN_SUPER_REWARD`) is evidenced in buy-mode `100002300` round-007 step-014.

`res.ps` is a non-empty column-major 5×3 integer board. Symbols 1–10 pay. Symbol 100 is Scatter. During the monster feature, zeroes are feature placeholders whose visible monster/wild identity is carried by `f.loc`, `f.a`, `f.r` and `f.rbs`. A win connects identical symbols from reel one across adjacent reels; each next position must remain on the same row or move one row. Three, four and five-reel payouts are the values in `rules-core.json`; `res.wa[].wy` is the ways count and `res.wa[].ws` contains the contributing cells.

Two Scatters start an evidenced monster mode (`f.nt` 1 or 2). Saved complete chains cover `f.gt`/`f.nt` 1, 2 and 3 and terminate only at `f.nt=0`. `f.h`, `f.a`, `f.loc`, `f.r` and `f.rbs` are preserved on every feature response. `f.gt=4` (`FREESPIN_SUPER_REWARD`) is wire-evidenced in buy-mode `100002300` round-007 step-014 and is emitted only from that captured type=4 corpus.

Redis uses DB 15 only. Ordinary miss/win: `PerKeyList_000002300` + `BetLog:000002300:%06d`. Purchase buckets stay on distinct prefixes and never share a LIST with ordinary members: `MaryKeyList_000002300` + `MaryLog:000002300:%06d` (type=3 ×60), `MaryKeyList_100002300` + `PerKeyList_100002300` + `MaryLog:100002300:%06d` (type=4 ×500), `MaryKeyList_200002300` + `PerKeyList_200002300` + `MaryLog:200002300:%06d` (type=5 ×200). Type=3 does not write `PerKeyList_000002300` because that index is ordinary. Members are compact ASCII (`MS1` ordinary, `MS2` buy). Ordinary and purchase centi-multipliers are both `roundTotalWin / baseBet × 100`; the purchase multiple affects the charged amount only and never changes the Redis multiplier. One member encodes all steps. The Controller claims once at paid start from the matching prefix and projects every later `type=2` from the same member. Empty Redis fails with an explicit 503 envelope.
