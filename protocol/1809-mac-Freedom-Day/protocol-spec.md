# Freedom Day 1809 增量协议规格

本规格只覆盖 2026-09-01 变牌、纵向空框、普通空奖 ×2 频率与其直接运行时链路。规则身份为
`freedom-day-1809-v2-defect-fix`，SHA-256 为
`235af93ec1e76cecf4816ab889bb1924113501faa79714b372473261367e6986`。

主盘 `prop` 固定 30 项，按 6 列、每列从上到下 5 格排列；`trl` 固定 4 项，属于第 2–5 列上方。
前端先按每列 5 项展开 `prop`，再反转每列用于自下向上布局。因此消除后的未消除符号保持列内顺序并落向列底，
新符号只能进入列顶空位；`trl` 未消除符号保持顺序向左补位，新符号从右侧进入。

`grids` 的每一项是一组同列、连续、同符号的占格索引，长度就是前端符号高度。合法高度为 2–4，首尾列只能
使用单格符号。`gf` 与 `sl` 必须完整引用 `grids` 中的一组，分别投影金框与银框；二者不能重叠。普通中奖合并
符号整组消除；金/银框中奖时前端读取下一页对应结构进行变形，不能把未中奖的合并组拆分、改高或改框。

相邻页必须由前页加协议事件重建：仅 `win_arr[].p`/`h` 指向的中奖单元可被消除；未消除主盘单元按上述重力
映射，未消除顶部单元按横向补位映射。任何幸存格换符号、合并组吞入幸存格、占格跨列、组内符号不一致或孤立
`gf/sl` 都使完整 Round 非法。RoundFactory 生成后、Controller 领取前及 Redis 写入前使用同一独立 Codec 门禁。

普通付费独立 LOSS 先由正式权重生成并由 `FreedomDayResultUtil` 复核为 0 倍、无中奖、无免费状态。缺陷策略仅对
已经确认的 LOSS 生效：50% 保留原基线 LOSS，50% 替换为同权重体系下 Ball 权重临时为零的实时 LOSS，并再次独立
复核。由此空奖含 ×2 的条件概率降为修改前的 50%，中奖候选、中奖概率、玛丽/购买模式及倍率结算不进入该策略。

每次付费起点一次生成完整 Round 并分配 `roundKey`；HTTP 每次只投影 `deliveryIndex` 指向的下一 Delivery。相同
幂等键只返回相同结果，不推进索引。Init 可恢复当前 Round 最近已投影 Delivery，History 保存实际领取顺序、牌面、
倍率、`roundKey` 与 `deliveryIndex`。

## 独立无奖 Spin 标记（2026-09-14）

1809 的 Redis member 以 ASCII `|` 分隔 Spin。整个 Spin token 为 `#` 时，解析器调用 `FreedomDayIndependentLossGenerator`，按普通/免费入口实时生成一张真实零倍盘。`0` 仍是原牌面占格编码的一部分，不是无奖标记。示例：`完整触发及连消编码|#|完整中奖连消编码|#`；普通独立零倍整局 member 为 `#`。

只有单页、不中奖、不新增免费次数、且对前后 Spin 无牌面依赖和状态增量的 Spin 可替换。免费次数仍消耗一次，累计倍率沿用原值。连消链的任何页（含无奖结束页）、免费触发/重触发盘均保留。中奖与否必须由 ResultUtil 实算，不依据整数截断、结果标签或金额覆盖判断。

生成器先复核原始完整局，再编码；正式 Loader 与离线 Pack 共用 CompleteRoundCodec，零倍按倍率 0 写索引和 List，仍执行 ZADD + RPUSH + LTRIM。解析一次得到完整具体牌面，后续投影、幂等请求和 History 复用该完整局，不重复随机解码。旧 34/68 字符成员保持兼容。已有 Redis 数据无需迁移，需先升级消费者解析器再使用新 Loader。
